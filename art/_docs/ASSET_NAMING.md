# Asset ID и именование файлов

Версия: 1.0  
Статус: обязательное правило для всех визуальных ассетов

## 1. Главное правило

Asset ID выдаётся один раз и навсегда. Освободившийся идентификатор **никогда** не выдаётся другому объекту. Отменённый ассет получает статус `deprecated` и остаётся в реестре вместе со своим номером.

Asset ID — единственный ключ, по которому связаны каталог на диске, запись в `asset-manifest.json`, файл метаданных, экспорт в игру и, при наличии, предмет игровых данных.

## 2. Формат

```text
СЕМЕЙСТВО-ПОДТИП-НОМЕР
```

Только заглавные латинские буквы, цифры и дефис. Номер — две цифры с ведущим нулём: `01`, `02`, … `99`.

Когда семейство перерастает 99 позиций, нумерация продолжается тремя цифрами (`100`, `101`, …). Уже выданные двузначные идентификаторы при этом **не переименовываются**: `WPN-MELEE-07` и `WPN-MELEE-100` спокойно живут рядом. Сортировка ведётся по числовому значению, а не по строке.

## 3. Семейства

### Персонажи

```text
CHAR-BASE-XX     базовые тела
CHAR-PLAYER-XX   готовые сборки игрока
CHAR-NPC-XX      мирные жители, торговцы, ремонтники, ликвидаторы
```

### Враги

```text

MOB-IND-XX       промышленные и автоматические
MOB-VOID-XX      войдовые
```

### Одежда и броня


## 4. Именование файлов

Каждый файл начинается с Asset ID, затем идёт назначение, затем уточнение. Разделитель — подчёркивание, всё в нижнем регистре кроме самого ID.

```text
<ASSET-ID>_<назначение>[_<уточнение>][_v<версия>].<расширение>
```

### Концепты и референсы

```text
CHAR-BASE-01_concept_front.png
CHAR-BASE-01_concept_back.png
CHAR-BASE-01_concept_side.png
CHAR-BASE-01_concept_iso.png
CHAR-BASE-01_concept_sheet.png
CHAR-BASE-01_ref_kirza-boots.jpg
```

### Исходники

```text
CHAR-BASE-01_source.blend
WPN-ENG-01_source.blend
```

### Текстуры

```text
CHAR-BASE-01_albedo.png
CHAR-BASE-01_normal.png
CHAR-BASE-01_roughness.png
CHAR-BASE-01_metallic.png
CHAR-BASE-01_ao.png
CHAR-BASE-01_emissive.png
```

### Риг и анимации

```text
CHAR-BASE-01_rig.blend
MOB-IND-01_anim_startup.blend
```

Общие humanoid-анимации именуются по действию, а не по ассету, и лежат в `art/animations/humanoid/`:

```text
SKEL-HUMANOID-01_walk_forward.blend
SKEL-HUMANOID-01_attack_melee_light.blend
```

### Игровой экспорт

```text
CHAR-BASE-01_game.glb
WPN-ENG-01_game.glb
```

## 5. Версии

Рабочие итерации допускают суффикс `_v2`, `_v3`. Утверждённый файл суффикса не имеет: побеждает всегда файл без версии, остальные считаются черновиками.

Запрещены имена:

```text
final.png
final2.png
new_final.png
weapon_new.glb
model_good.blend
концепт итог.png
```

Запрещены пробелы, кириллица и заглавные буквы в именах файлов. Кириллица живёт в полях `nameRu` и `description`, а не в путях.

## 6. Связь с игровыми данными

Если ассет изображает предмет, уже существующий в игре, его запись в реестре содержит поле `gameItemId` со значением из `ItemId` в `app/game-items.ts` — например `respiratorIp7`. Это единственная точка связи между художественным и игровым учётом; дублировать игровые характеристики в художественных метаданных запрещено.

# SAMOSBOR — рабочие правила репозитория

Этот файл — первое, что читается в новой сессии. Он описывает, что это за проект, как он устроен и по каким правилам в нём работают.

## Что это за игра

Изометрическая системная action RPG / hack and slash в мире бесконечной Гигахрущёвки. Мир живёт в непрерывном времени независимо от героя.

Продуктовый и визуальный канон, который нельзя нарушать:

- изометрическая real-time action RPG / hack and slash;
- свободные билды без жёстких классов;
- системный живой мир;
- советско-индустриальная материальность, doomwave, оригинальный дизайн;
- города и крупные общественные пространства — монументальный сталинский ампир с архитектурным языком лучших станций метро Москвы и Санкт-Петербурга: церемониальные, красивые и одновременно давящие;
- никакого generic cyberpunk, обычного фэнтези и безликого серого лабиринта;
- у аномалий собственный язык SAMOSBOR.

Визуальные правила — `art/_docs/VISUAL_BIBLE.md`. Художественная рамка — `art/_docs/ART_DIRECTION.md`.

## Целевая платформа

**Только настольная PC-версия.** Мобильное управление, планшеты, телевизоры и пульты в скоуп не входят: на них не тратится время, новые фичи под них не проектируются. Существующие touch/TV-ветки кода — технический долг, а не поддерживаемая платформа.

**Аудио вне скоупа**: музыку и звук подбирает владелец проекта.

## Архитектура

Игровая логика не зависит от React, рендера и частоты кадров. Интерфейс получает сериализуемое состояние и отправляет команды обратно в симуляцию.

```
app/game-engine-base.ts   ядро: состояние мира, симуляция, ИИ, бой, таланты,
                          предметы, сохранения и миграции
app/game-engine.ts        тонкая обёртка: поверх ядра наслаиваются кампания,
                          сюжет, профессии, оборона, регион 544/545 и
                          world-системы; часть функций ядра переопределяется
app/game-combat-model.ts  числовая боевая модель, чистые функции без состояния
app/game-skills.ts        свободное дерево: шесть направлений, гибриды
app/game-prototype.tsx    игровой экран и HUD
app/world-navigation-overlay.tsx  мини-карта и глобальная карта
```

Обёртка над ядром: при добавлении логики в `game-engine.ts` нужно помнить, что она переопределяет функцию ядра целиком. Если у ядра есть приоритетное поведение (например, аварийная директива Самосбора важнее квестовой), обёртка обязана его пропустить вперёд.

## Развитие персонажа

Классов нет и не будет. Есть **одно общее дерево из шести направлений**: `power`, `guard`, `agility`, `precision`, `suppression`, `resonance`.

Архетип — **производное чтение** от того, куда вложено больше очков (`archetypeFor`), а не поле состояния и не выбор игрока. Нельзя вводить классы Tank, Rogue и подобные: направления возникают из комбинации талантов.

Боевые механики — data-driven: пассивные таланты меняют параметры блока, парирования и заряда через `DefenceTuning` / `ChargeTuning`, а не переписывают базовую боевую систему.

## Проверки

Перед коммитом системного изменения выполняются фактически, а не предполагаются:

```bash
npm run test:engine   # тесты ядра
npm run lint          # 0 ошибок
npm run build         # production build
npm test              # рендер-тест
```

Изменения игрового экрана дополнительно проверяются в браузере: `npm run dev`, затем Chromium (`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`) через Playwright. Скриншот смотрится глазами — «тесты зелёные» не доказывает, что экран не сломан.

Отсутствие запущенного CI не считается успешной проверкой.

## Правила работы

- Нашёл проблему — исправляй. Мешает старая система — переписывай. Устарела документация — обновляй.
- Не выдавать проектное решение за работающую механику. Если канон опережает код, это фиксируется явно.
- Не оставлять полуготовых реализаций и заглушек «на будущее».
- Комментарии — только там, где неочевидно **почему**. Не описывать, что делает код.
- Коммиты — смысловые и стабильные: репозиторий всегда в рабочем состоянии.

## Известный технический долг

- ID активных навыков сохранили старые префиксы веток (`force-`, `fire-`, `stealth-`, `bulwark-`, `engineer-`), хотя направления давно другие. Переименование требует отдельной миграции сохранений.
- Бюджет очков и пороги направлений в коде (`0/4/8/14`) не совпадают с ориентиром в README §6.3 (`1/5/10/15/20`, 20/33/10 очков). Расхождение зафиксировано в README §6.5.
- Ветки интерфейса под touch, геймпад и телевизор не поддерживаются и подлежат удалению.
- Визуальных ассетов в репозитории нет ни одного: вся визуальная часть существует только как стандарты и спецификации.

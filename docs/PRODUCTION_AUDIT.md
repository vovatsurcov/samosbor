# Production audit: SAMOSBOR перед переходом в Unity

Версия: 1.0  
Дата: 2026-08-07  
Метод: полный обход репозитория (`art/`, `public/`, `docs/`, `app/`) на предмет реальных бинарных ассетов и производственной документации. Ни один Unity-инструмент не запускался — раздел 3 объясняет, почему.

## 1. Главный факт аудита

**В репозитории нет ни одного бинарного визуального ассета.** Проверено по всему дереву (кроме `node_modules`):

```bash
find . -iname "*.png" -o -iname "*.jpg" -o -iname "*.fbx" -o -iname "*.blend" \
     -o -iname "*.glb" -o -iname "*.obj" -o -iname "*.psd"
```

Совпадения — только четыре SVG-иконки шаблона Next.js в `public/` (favicon, file, globe, window) — не игровые ассеты.

`art/asset-manifest.json` содержит 32 записи первого производственного батча (см. предыдущий этап), **все 32 в статусе `planned`**. Ни одна не дошла даже до `concept`. Каталоги `art/**/CHAR-BASE-01/`, `CHAR-BASE-02/` существуют, но пусты (только `.gitkeep` и `meta/asset.meta.json` с пустыми путями).

Это означает: production audit по art-контенту — это аудит **документации и стандартов**, а не готовых ассетов. Ниже — что реально есть (спецификации, паттерны, ограничения) и что отсутствует полностью (сами файлы).

## 3. Почему Unity-часть этого этапа не может быть выполнена и проверена в этой сессии

Это блокер, а не техническая деталь, и я обязан сказать о нём прямо, а не тихо сделать вид, что что-то «запущено».

```
$ which unity unityhub dotnet mono
(пусто — ничего не найдено)
```

В этом окружении нет ни Unity Editor/Hub, ни `dotnet`/`mono` для компиляции C#, ни GPU/дисплея для рендеринга 3D-сцены. Это CLI-окружение с доступом к файловой системе, Node.js и Chromium (headless) — то, чем я проверял браузерную версию.

Из перечня в «Definition of Done» физически недостижимы в этой сессии:

- «Unity-проект запускается»;
- «герой отображается и управляется»;
- «камера работает»;
- «результаты ручного Unity playthrough»;
- «всю цепочку можно пройти вручную... без ручного вмешательства разработчика».

Я могу **написать** файлы: структуру `Assets/`, C#-скрипты архитектуры (player/input/movement/combat/stats/...), `ProjectSettings/*.asset` в текстовом виде, `.gitignore` для Unity. Но:

1. Unity крайне требователен к точному формату сериализации: `.meta`-файлы с GUID на каждый ассет, версия `ProjectVersion.txt`, формат YAML-сцены, привязанный к конкретной версии редактора. Файлы, написанные вручную без Editor, с высокой вероятностью откажутся открываться или будут повреждены при первом сохранении в реальном Unity.
2. Я не могу проверить компиляцию C# (нет `dotnet`/`mono`), то есть не могу гарантировать, что написанный код вообще собирается.
3. Я не могу увидеть результат — ни скриншот сцены, ни лог консоли Unity, ничего визуального.

Иными словами: я могу подготовить **текстовый скаффолд и архитектуру**, но заявить «этап пройден по Definition of Done» было бы неправдой — ни один пункт про «запускается / отображается / управляется / playthrough» не проверен и не может быть проверен здесь.

## 4. KEEP / FIX / REBUILD / MISSING (сводно)

**KEEP** — переносится практически без изменений:
- числовая боевая модель (`app/game-combat-model.ts`) — прямой порт арифметики;
- игровые данные предметов, врагов, направлений дерева как конфиг (JSON/ScriptableObject);
- геометрия карт этажей как layout-референс для блокинга уровня;
- художественные стандарты именования и точек крепления (`art/_docs/ASSET_NAMING.md`, `ATTACHMENT_POINTS.md`) — они писались с прицелом на Unity Humanoid с самого начала.

**FIX** — небольшая доработка:
- ничего в этой категории: либо готово как данные (KEEP), либо отсутствует полностью (MISSING). Промежуточного «почти готового визуального» нет.

**REBUILD** — концептуально подходит, технически непригодно:
- ничего: нет ни одного визуального артефакта, который можно было бы технически забраковать. Вся визуальная часть в категории MISSING.

**MISSING** — реально нет:
- любая 3D-геометрия: герой, NPC, враги, оружие, броня, окружение;
- любые анимации;
- любые материалы/текстуры/шейдеры;
- любой VFX;
- сам Unity-проект (папка, `ProjectSettings`, пакеты).

**BLOCKERS** для первого Unity-среза:
1. Unity Editor физически недоступен в этой среде — нельзя создать, открыть или проверить проект здесь.
2. Нет ни одной 3D-модели персонажа — без неё нет ни Humanoid Avatar, ни анимаций, ни боевого прототипа с реальным силуэтом.
3. Нет ни одного окружения — «первый environment slice» требует геометрии, которой физически не существует.

## 5. Что это значит для порядка работы

Раздел 2 показывает: единственный полностью переносимый актив — **числовая модель и игровые данные**. Всё визуальное — с нуля. Это не «доработать», а «произвести впервые», и произвести физически негде — в этой сессии нет инструментов создания 3D-контента (нет модельера, нет генератора изображений с доступом из CLI, нет Unity для сборки из примитивов).
